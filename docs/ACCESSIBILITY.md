# Accessibility (WCAG 2.2 AA)

AirWise is used by anxious families, often on a phone and sometimes by elders, so it is built to be understandable and operable by everyone.

| Criterion                         | Implementation                                                                                                                                                                                                          | Evidence                                                        |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 1.1.1 Non-text content            | Impact bars are `role="img"` with the numbers in their name; emoji icons sit next to text                                                                                                                               | `e2e/app.spec.ts`                                               |
| 1.3.1 Info and relationships      | Every control has a real `<label>`; related radio buttons are `fieldset`/`legend` groups; the day plan and actions are lists                                                                                            | axe-core (unit and real browser)                                |
| 1.3.5 / 3.1.2 Language            | Hindi and Marathi briefings carry the right `lang` attribute                                                                                                                                                            | `client/App.test.tsx`                                           |
| 1.1.1 / 1.4.5 Alternative formats | **Read aloud** speaks the briefing with the browser's own English, Hindi or Marathi voice (hidden when unsupported), helping low-vision and low-literacy readers                                                        | `client/components/Tools.tsx`, `client/App.test.tsx`            |
| 1.3.1 Tables and disclosures      | The commute comparison is a real `<table>` with a caption and `th scope` for columns and rows, in a scrolling wrapper so it never forces horizontal page scroll; DIY steps and myths use native `<details>`/`<summary>` | `client/components/Commute.tsx`, `client/components/Indoor.tsx` |
| 1.4.1 Use of colour               | AQI levels always show the category **name**; day-plan windows have text and a symbol (✔ ▲ ✖)                                                                                                                           | `client/components/Results.tsx`                                 |
| 1.4.3 / 1.4.11 Contrast           | Every text pair, all six AQI level colours and the focus ring pass in light **and** dark themes                                                                                                                         | `shared/contrast.test.ts`, real-browser axe                     |
| 1.4.10 Reflow                     | Single column on small screens, no horizontal scroll at 320 px                                                                                                                                                          | `e2e/app.spec.ts`                                               |
| 2.1.1 Keyboard                    | Everything works by keyboard; Enter asks a question; first Tab reaches the skip link                                                                                                                                    | `e2e/app.spec.ts`                                               |
| 2.4.1 Bypass blocks               | Skip-to-content link                                                                                                                                                                                                    | `client/App.tsx`                                                |
| 2.5.8 Target size                 | Radios and checkboxes are 24 px, buttons ≥ 40 px                                                                                                                                                                        | `client/styles.css`                                             |
| 3.3.x Input                       | Numeric fields are clamped to valid ranges, so there is no error to recover from; labels explain units                                                                                                                  | `client/components/Fields.tsx`                                  |
| 4.1.2 Name, role, value           | Filter buttons use `aria-pressed`; progress is announced in text                                                                                                                                                        | axe-core                                                        |
| 4.1.3 Status messages             | One polite live region for progress and results; possible emergencies use `role="alert"`                                                                                                                                | `client/App.test.tsx`                                           |
| Motion, print                     | `prefers-reduced-motion` respected; print stylesheet hides inputs                                                                                                                                                       | `client/styles.css`                                             |

**Real-browser evidence:** `e2e/app.spec.ts` runs axe-core (WCAG 2.0–2.2 A/AA plus best practices, including true colour contrast) on the production build in light and dark themes, plus keyboard order, 320 px reflow and offline use. Result: 0 violations. ESLint `jsx-a11y` runs on every commit.
